Publicar mi blog con un solo comando

Cómo automatizar la copia de los archivos de Apache, registrar cambios con Git y actualizar tu web pública sin memorizar todos los comandos.

1. ¿Qué vamos a conseguir?

Seguiremos creando y probando las páginas en Apache local. Cuando estén listas, ejecutaremos publicar-web y el script preparará el envío a GitHub.

Geany + Apache/var/www/html/
Script Bash + Git~/mi-web-github/
GitHub PagesWeb pública

El script copiará index.html, entradas.js, entradas.json y los archivos HTML de publicaciones/. Después mostrará los cambios y pedirá confirmación antes de subirlos.

Antes de publicar: revisa que no haya nombres, teléfonos, correos, textos privados u otros datos que no quieras mostrar. Los commits pueden conservar versiones anteriores.

2. Crear el script en MAX 12

Abre una terminal gráfica como usuario madrid (no como root) y ejecuta:

mkdir -p ~/bin
geany ~/bin/publicar-web

Copia en Geany el siguiente script completo y guárdalo con Ctrl + S.

#!/bin/bash
set -e

ORIGEN="/var/www/html"
DESTINO="$HOME/mi-web-github"

echo "=================================="
echo " PUBLICADOR DE MI BLOG"
echo "=================================="

# Comprobar que existe el repositorio local
if [ ! -d "$DESTINO/.git" ]; then
    echo "ERROR: no encuentro el repositorio en $DESTINO"
    exit 1
fi

cd "$DESTINO"

# Copiar únicamente los archivos de nuestro blog
cp "$ORIGEN/index.html" .
cp "$ORIGEN/entradas.js" .
cp "$ORIGEN/entradas.json" .

# Copiar las publicaciones HTML sin borrar las anteriores
mkdir -p publicaciones
cp "$ORIGEN"/publicaciones/*.html publicaciones/

echo ""
echo "Cambios detectados:"
git status --short

if [ -z "$(git status --porcelain)" ]; then
    echo "No hay cambios que publicar."
    exit 0
fi

echo ""
read -r -p "¿Quieres publicar estos cambios? (s/n): " RESPUESTA

if [ "$RESPUESTA" != "s" ]; then
    echo "Publicación cancelada."
    exit 0
fi

git add index.html entradas.js entradas.json publicaciones/

# Evitar un commit vacío si hubiera otros cambios ajenos
if git diff --cached --quiet; then
    echo "No hay cambios preparados para publicar."
    exit 0
fi

git commit -m "Actualizar blog $(date +%Y-%m-%d_%H:%M)"
git push

echo ""
echo "¡Cambios enviados a GitHub!"
echo "https://elumbreras23-creator.github.io/"

El script no borra automáticamente los archivos antiguos en GitHub. Tampoco copia otras aplicaciones de Apache, como Moodle o WordPress. Si GitHub solicita credenciales, utiliza tu token, nunca tu contraseña habitual.

3. Dar permiso de ejecución y probarlo

chmod +x ~/bin/publicar-web
~/bin/publicar-web

Verás la lista de archivos modificados y la pregunta ¿Quieres publicar estos cambios? (s/n):. Escribe s para continuar o n para cancelar.

Importante: el script no publica nada hasta que confirmas. Si no hay cambios, termina sin crear commits.

4. Ejecutarlo desde cualquier carpeta

Comprueba si ~/bin ya está en tu variable PATH:

echo "$PATH"

Si no aparece /home/madrid/bin, añade esta línea al final de ~/.bashrc:

export PATH="$HOME/bin:$PATH"

Recarga la configuración:

source ~/.bashrc

Desde ese momento podrás escribir simplemente:

publicar-web

5. Publicar una nueva entrada: ejemplo real

  1. Guarda una página nueva en /var/www/html/publicaciones/, por ejemplo automatizar-publicacion-github.html.
  2. Abre /var/www/html/entradas.json y añade un objeto con título, fecha, descripción y URL. Recuerda separar los objetos con comas.
  3. Comprueba la entrada en http://localhost/ y abre su enlace para verificar que funciona.
  4. Ejecuta publicar-web, revisa los cambios y confirma con s.
  5. Espera a que GitHub Pages termine el despliegue y comprueba la web pública.

Ejemplo de objeto para entradas.json:

{
  "titulo": "Automatizar la publicación con Git",
  "fecha": "2026-11-15",
  "descripcion": "Guía para actualizar el blog desde MAX 12 con un script Bash.",
  "url": "publicaciones/automatizar-publicacion-github.html"
}

Este bloque es un objeto dentro del array de entradas.json, no un archivo JSON completo. Si lo añades después de otra entrada, pon una coma entre ambos objetos.

6. Entender los comandos Git que automatizamos

ComandoPara qué sirve
git statusMuestra archivos nuevos o modificados.
git addPrepara los cambios que queremos guardar.
git commitCrea una versión en el historial local.
git pushEnvía los commits al repositorio remoto.
git log --oneline -5Permite ver los últimos cinco commits.

7. Problemas habituales

Git dice «Everything up-to-date»

No hay commits nuevos para enviar. Comprueba que has guardado los cambios en /var/www/html/ y que el script los ha copiado a ~/mi-web-github/.

El navegador sigue mostrando la versión anterior

Comprueba el último despliegue en GitHub → Actions. Si terminó correctamente, prueba Ctrl + F5 o una ventana privada.

Geany muestra «cannot open display»

Abre una terminal desde el escritorio gráfico como usuario madrid, en lugar de una sesión su - madrid sin acceso al entorno gráfico.

El script indica «Permission denied»

Comprueba que has ejecutado chmod +x ~/bin/publicar-web y que los archivos del blog se pueden leer con tu usuario.

He eliminado una entrada pero sigue en GitHub

Este script copia y actualiza, pero no elimina archivos remotos. Las eliminaciones se deben revisar y gestionar por separado para evitar borrar contenido accidentalmente.

Quiero publicar información que antes era privada

Comprueba el contenido antes de subirlo. Si ya publicaste datos sensibles, modificarlos en un commit nuevo no los elimina del historial anterior de Git.

8. Tu rutina a partir de ahora

Editar → probar en localhost → ejecutar publicar-web → confirmar → comprobar GitHub Pages.
