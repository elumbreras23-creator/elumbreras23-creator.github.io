Publicar mi blog con Git y GitHub Pages

Una guía paso a paso para crear nuevas entradas en local, probarlas con Apache y subirlas a Internet con seguridad.

Nivel: iniciaciónHTML + JSON + JavaScriptGitHub Pages

El mapa de nuestro proyecto

Trabajamos con tres ubicaciones distintas. Git no lee automáticamente los cambios que hacemos en Apache: hay que copiarlos al repositorio antes de publicarlos.

Geany + Apache
/var/www/html/→ copiar →Repositorio Git local
~/mi-web-github/→ git push →GitHub Pages
Web pública
La web pública es elumbreras23-creator.github.io. El repositorio está en GitHub.
1

Crear una nueva publicación en Apache

Abre Geany desde la sesión gráfica de madrid y crea, por ejemplo, /var/www/html/publicaciones/guia-git-github-pages.html. Esta guía que estás leyendo puede ser ese archivo.

Comprueba que Apache sirve la página en:

http://localhost/publicaciones/guia-git-github-pages.html

Si vas a publicar otra práctica, sustituye el nombre del archivo por el que corresponda.

No trabajes como root si no es necesario. Si Geany muestra «cannot open display», ábrelo desde una terminal nueva de tu escritorio gráfico como usuario madrid.
2

Registrar la entrada en el índice JSON

Abre /var/www/html/entradas.json. Es una lista de objetos separados por comas. Añade uno nuevo dentro del array, sin borrar los existentes:

{
  "titulo": "Guía práctica de Git y GitHub Pages",
  "fecha": "2026-11-15",
  "descripcion": "Aprende a publicar y actualizar el blog desde MAX 12.",
  "url": "publicaciones/guia-git-github-pages.html"
}

Si no es el primer objeto, recuerda la coma que lo separa del anterior. No pongas coma después del último objeto. Cambia la fecha cuando corresponda.

Recarga http://localhost/ y verifica que la entrada aparece en «Últimas publicaciones» y que su enlace funciona.

Nuestro entradas.js carga el JSON mediante fetch(). Para probarlo, abre la web desde http://localhost/, no haciendo doble clic sobre el archivo HTML.
3

Copiar los cambios al repositorio local

En una terminal como usuario madrid, copia la publicación y el índice actualizado:

cp /var/www/html/publicaciones/guia-git-github-pages.html \
   ~/mi-web-github/publicaciones/
cp /var/www/html/entradas.json ~/mi-web-github/

Si también has modificado la página principal, copia además:

cp /var/www/html/index.html ~/mi-web-github/

Si has modificado el script, copia entradas.js de la misma manera. No copies todo /var/www/html/: allí también tienes otros proyectos, como Moodle y WordPress, que no pertenecen a este repositorio.

4

Revisar los cambios con Git

cd ~/mi-web-github
git status
git diff -- entradas.json index.html
git diff --cached

git status te dice qué archivos cambiaron. git diff muestra modificaciones de archivos ya seguidos, antes de prepararlos; git diff --cached muestra los cambios preparados para el próximo commit.

Antes de publicar, revisa que no hayas incluido información personal, contraseñas, tokens, claves o archivos privados. GitHub conserva el historial de los commits incluso si después editas o borras el contenido.
5

Preparar y guardar una versión

Añade únicamente los archivos de esta publicación:

git add entradas.json publicaciones/guia-git-github-pages.html
git status
git diff --cached

Si la revisión es correcta, guarda el cambio:

git commit -m "Añadir guia de Git y GitHub Pages"

Un commit guarda una versión en tu equipo; todavía no la publica.

6

Subir a GitHub y comprobar Pages

git push

Si Git solicita usuario y contraseña por HTTPS, utiliza tu usuario de GitHub y, como contraseña, tu token personal. No compartas ese token ni lo incluyas en archivos o capturas.

Espera a que GitHub Pages termine de desplegar y visita tu blog público. Prueba la nueva entrada y recarga con Ctrl + F5 si el navegador conserva la versión anterior.

La secuencia esencial es: editar → probar en localhost → copiar → git status → git add → git commit → git push → comprobar la web.

Comandos de referencia

ComandoPara qué sirve
git statusVer qué ha cambiado y qué está preparado.
git diffExaminar cambios todavía no preparados.
git add archivoSeleccionar un archivo para el siguiente commit.
git commit -m "mensaje"Guardar una versión local con una descripción.
git pushEnviar commits locales a GitHub.
git pull --ff-onlyTraer cambios remotos si la actualización puede hacerse sin mezclar historiales divergentes.
git log --oneline -5Ver las cinco últimas versiones.
git remote -vComprobar la dirección del repositorio remoto.
Si editas archivos directamente en GitHub desde el navegador, antes de volver a publicar desde MAX 12 conviene ejecutar git pull --ff-only y resolver cualquier aviso antes de continuar.

Problemas frecuentes

«Nothing to commit» / «Everything up-to-date»

Git no detecta cambios en el repositorio local. Quizá modificaste /var/www/html/ y olvidaste copiar el archivo a ~/mi-web-github/.

La web pública sigue mostrando una versión antigua

Comprueba primero el archivo en GitHub, después el estado del despliegue en Settings → Pages y Actions. Por último, prueba una ventana privada o una recarga forzada.

«Authentication failed»

GitHub no admite tu contraseña habitual para git push por HTTPS. Usa un token con permiso de escritura sobre Contents del repositorio.

La entrada aparece pero el enlace falla

Comprueba que el campo url en entradas.json coincide exactamente con el nombre del HTML dentro de publicaciones/, incluidas mayúsculas y minúsculas.

El JSON deja de cargar

Revisa comas, llaves y comillas dobles. Un error de sintaxis puede impedir que entradas.js muestre las publicaciones.
