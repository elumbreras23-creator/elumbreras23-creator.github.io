Cómo publicar una nueva entrada directamente en GitHub

Crea y publica contenidos desde cualquier ordenador con Internet. Sin Apache, sin Geany y sin comandos de Git.

Aplicado a nuestro blog de prácticas de SMR
En esta guía aprenderás:

1. Cómo funciona2. Subir el HTML3. Añadirlo al índice4. Comprobar5. Editar en GitHub6. Volver a MAX 12

1. Nuestro nuevo método de trabajo

Hasta ahora creábamos las páginas en /var/www/html/publicaciones/, las probábamos con Apache y después las enviábamos con Git. Ahora podemos publicar directamente en el repositorio de GitHub desde Firefox o cualquier navegador.

Archivo HTMLLo creas en cualquier ordenador
GitHubSubes el archivo y editas el JSON
GitHub PagesDespliega automáticamente tu blog
Dos archivos, dos funciones: el HTML contiene la práctica; entradas.json le dice a entradas.js qué prácticas mostrar en «Últimas publicaciones». No necesitas modificar entradas.js para cada entrada nueva.

2. Subir esta misma guía a GitHub (primera práctica)

Vamos a utilizar este archivo como ejemplo. Su nombre es publicar-directamente-en-github.html.

  1. Descarga y guarda el archivo HTML en el ordenador que estés utilizando.
  2. Abre el repositorio elumbreras23-creator.github.io e inicia sesión.
  3. Entra en la carpeta publicaciones. Es importante subir el HTML dentro de esa carpeta.
  4. Selecciona Add file → Upload files (en algunas pantallas, el botón aparece como +).
  5. Arrastra publicar-directamente-en-github.html o utiliza el selector de archivos.
  6. Escribe un mensaje de commit, por ejemplo: Añadir guía para publicar desde GitHub. Selecciona guardar directamente en main, si GitHub permite esa opción, y confirma el cambio. Si exige una rama y una solicitud de cambios, complétalas hasta fusionar en main.

GitHub guardará el archivo en el repositorio, pero todavía no figurará en el listado del blog hasta completar el siguiente paso.

Dirección directa esperada de esta guía:
https://elumbreras23-creator.github.io/publicaciones/publicar-directamente-en-github.html

3. Añadir la nueva entrada a «Últimas publicaciones»

Ahora tienes que informar al índice del blog de que existe la nueva publicación.

  1. En el repositorio, vuelve a la carpeta principal y abre entradas.json.
  2. Pulsa el lápiz («Edit this file»).
  3. Dentro del array [ ... ], añade el siguiente objeto. Sustituye la fecha y la hora de ejemplo por las reales.
{
  "titulo": "Publicar directamente en GitHub sin Apache",
  "fecha": "2026-11-16T11:00:00",
  "descripcion": "Guía para subir entradas HTML al blog desde cualquier ordenador y registrarlas en JSON.",
  "url": "publicaciones/publicar-directamente-en-github.html"
}
Atención a las comas: cada objeto del array debe estar separado del siguiente por una coma. Si lo añades al final, pon una coma tras el objeto anterior, pero no añadas una coma después del último objeto. No crees un segundo par de corchetes [ ].
  1. Guarda el cambio mediante Commit changes y confirma que llega a main.

La hora se escribe en formato de 24 horas con una T entre fecha y hora. Ejemplo: 2026-11-16T17:30:00. Nuestro JavaScript usa esta información para ordenar y agrupar las entradas por día. Si no pones hora, la entrada podrá seguir mostrándose, pero sin ese dato.

4. Comprobar el resultado público

  1. Abre la portada pública del blog.
  2. Espera a que finalice el despliegue de GitHub Pages. Puedes comprobar el estado en la pestaña Actions del repositorio.
  3. Actualiza con Ctrl + F5 si el navegador muestra una versión antigua.
  4. En «Últimas publicaciones», despliega la fecha correspondiente y localiza «Publicar directamente en GitHub sin Apache».
  5. Pulsa el título. Debe abrir esta misma guía.
Prueba superada: si puedes abrir la nueva página desde el índice del blog, habrás publicado una entrada completa sin pasar por Apache.

¿Se abre el HTML directamente, pero no aparece en el índice?

Revisa entradas.json: confirma que el objeto está incluido dentro del array, que las comas son correctas y que url coincide exactamente con el nombre y la carpeta del archivo HTML.

¿No aparece todavía el cambio?

Comprueba el commit en main y el estado de despliegue en Actions. Si la web conserva una versión anterior, prueba Ctrl + F5.

5. Modificar una publicación sin volver a subirla

Para corregir texto, quitar un botón o añadir instrucciones, tampoco necesitas MAX 12:

  1. Abre la página HTML dentro de la carpeta publicaciones del repositorio.
  2. Pulsa el lápiz para editar el archivo.
  3. Realiza el cambio en el código.
  4. Guarda con Commit changes y comprueba el resultado en la página pública.

Para trabajar cómodamente con muchas líneas de HTML, abre github.dev, el editor web similar a VS Code. Permite buscar texto, activar el ajuste de línea y guardar cambios con commits.

Para prácticas de alumnos: puedes compartir solo el enlace directo a su HTML. Si eliminas «Volver al blog» de la entrada, no habrá un acceso fácil a la portada desde esa página, aunque el resto de archivos de un repositorio público seguirá siendo accesible para quien conozca sus URL.

6. ¿Qué pasa con Apache y tu ordenador MAX 12?

Si publicas desde GitHub, tu servidor Apache no se actualiza automáticamente. Cuando vuelvas a utilizar MAX 12, sincroniza con cuidado:

  1. Comprueba primero si tienes cambios locales sin guardar, tanto en ~/mi-web-github/ como en los archivos de /var/www/html/.
  2. Si el repositorio Git local está limpio, ejecuta allí git pull --ff-only origin main.
  3. Solo después de comprobar qué cambió, copia a Apache los archivos correspondientes, evitando sobrescribir trabajo local pendiente.
cd ~/mi-web-github
git status
git pull --ff-only origin main
No ejecutes sin revisar el script antiguo publicar-web: copia archivos desde Apache y podría intentar enviar versiones antiguas de las páginas modificadas en GitHub. Si ambas versiones cambiaron, primero hay que compararlas y conservar lo que corresponda.

7. Resumen para futuras publicaciones

  • Crear o descargar un archivo .html.
  • Subirlo a la carpeta publicaciones en GitHub.
  • Guardar el commit en main.
  • Añadir título, fecha/hora, descripción y URL a entradas.json.
  • Guardar el segundo commit.
  • Verificar el despliegue y probar el enlace en el blog.

¡Ya puedes publicar contenidos para tus alumnos desde cualquier ordenador conectado a Internet!
